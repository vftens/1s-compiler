# GridCraft × 1S: план подключения Rust → Python

GridCraft (storytold/gridcraft v0.8.0, MIT OR Apache-2.0) — движок электронных таблиц
на Rust: чтение .xls/.xlsb/.ods/.xlsx, 500+ функций Excel, запись настоящего .xlsx
с формулами, форматами и условным форматированием. 1S — Python (GPLv3).

## Зачем это 1S (фокус-тир: миграция с 1С)

1. **Читать выгрузки 1С/BAS.** Отчёты 1С сохраняются в .xls — openpyxl его не читает.
2. **Сверка ОСВ после миграции.** Главный вопрос бухгалтера после переезда:
   «сошлись ли остатки?». Ответ — книга Excel, где каждая разница — живая формула,
   а не число, которому надо верить.
3. **Отчёты в .xlsx** из 1S без самописного генератора.

Это не новая витрина: модуль живёт в `src/migrate` и наследует тир `focus`.

## Варианты моста Rust → Python

| Вариант | Как | Плюсы | Минусы | Решение |
|---|---|---|---|---|
| 1. Процесс + JSON | `gridcraft-cli run --script steps.jsonl` | ноль сборки для пользователя, обновление = замена бинарника, падение движка не роняет 1S | ~10–50 мс на вызов | **Фаза 1, сделано** |
| 2. PyO3 / maturin | Python-модуль `gridcraft` из Rust | вызовы в памяти, без файлов | колёса под 3 ОС × версии Python, Rust в CI, ABI | Фаза 3, только при замеренной нужде |
| 3. MCP-сервер | `gridcraft-cli mcp` | агенты (Open Executive, Claude) правят таблицы | не для кода 1S | Параллельно, для AI-команды |
| 4. WASM | сборка web | таблица в браузере (демо на 1s-compiler.ru) | только фронтенд | Позже, для сайта |

## Фаза 1 — сделано

- `src/migrate/gridcraft.py` — класс `GridCraft`: `run(steps)`, `read()`, `info()`,
  `evaluate()`, `convert()`. Шаги идут через JSONL-файл: значения не проходят через
  shell, нет лимита длины argv. Поиск бинарника: `$GRIDCRAFT_CLI` → PATH → `bin/`.
- `src/migrate/reconcile.py` — чтение ОСВ (CSV напрямую, .xls/.xlsx через GridCraft),
  сравнение по счетам (допуск 0,005), запись книги сверки: Δ = `=N(C2)-N(G2)`,
  статус `=IF(...;"OK";"РАСХОЖДЕНИЕ")`, итоги `SUM`, красная/зелёная подсветка,
  закреплённая шапка. Счета хранятся как текст («41.010» ≠ 41,01).
- CLI: `python -m src.cli migrate reconcile osv_1c.xls osv_odoo.xlsx -o sverka.xlsx
  [--lang ru|uk|en] [--left-label BAS] [--right-label Odoo]`.
  Код выхода: 0 — сошлось, 1 — есть расхождения, 2 — ошибка (удобно для CI/скриптов).
- Тесты `tests/test_gridcraft_bridge.py`: чистые тесты без GridCraft + `live`-тесты,
  которые запускаются, только если найден `gridcraft-cli`
  (результат проверяется `gridcraft-cli check`: формулы пересчитаны, пакет валиден).

## Фаза 2 — поставка бинарника (следующий спринт)

1. CI (`build.yml`): шаг `cargo install --git https://github.com/storytold/gridcraft
   --tag v0.8.0 gridcraft-cli --root build/gc`, кэш `~/.cargo`, копия в `bin/`.
2. `packaging/*.spec`: добавить `bin/gridcraft-cli[.exe]` в `binaries`.
3. Положить `LICENSE-MIT`/`LICENSE-APACHE` GridCraft в `third_party/gridcraft/`
   и строку в NOTICE. Apache-2.0 совместима с GPLv3; бренд GridCraft не используем как свой.
4. Без бинарника 1S работает как раньше — сверка CSV↔CSV не требует GridCraft
   для сравнения, только для записи .xlsx.

## Фаза 3 — PyO3 (только по метрике)

Порог: если сверка/отчёт делает >100 вызовов движка или вызов >1 с на типовой ОСВ.
Тогда — отдельный репозиторий `gridcraft-py` (maturin, abi3, py3.10+), вне workspace
GridCraft, тот же API, что у класса `GridCraft`, — код 1S не меняется.

## Риски

- **v0.8.0, молодой проект** → версия закреплена тегом, мост узкий (5 методов), легко заменить.
- **Изменения JSON-команд** → live-тесты в CI ловят поломку при обновлении тега.
- **Размер дистрибутива** → +~15–25 МБ бинарника; опционально в «лёгкой» сборке.

## Метрика успеха

Бухгалтер получает `sverka.xlsx` за одну команду и видит расхождения за 10 секунд.
Демо этого — главный сценарий лендинга 1s-compiler.ru («переезд с 1С без страха»).
